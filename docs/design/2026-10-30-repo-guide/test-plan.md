# 7단계 테스트 계획: 새 저장소 안내자

- 설계: [README.md](README.md)
- 1차 테스트 계획: [../2026-10-28-flow-review/test-plan.md](../2026-10-28-flow-review/test-plan.md). 실행 규칙(CI, 로컬 리뷰, 증적)은 1차와 같다

## 등급과 범위

| 항목 | 값 |
|---|---|
| 등급 | L1(바뀐 기능, 개발 환경, 작성자 실행)과 CI. 새 화면이라 독립 검수 3회 |
| 실행 환경 | `dev`: 코어 단위 시험(vitest), 데스크톱 E2E(Playwright for Electron), CI는 ubuntu와 macOS |
| 실기기 | 없음. 데스크톱 앱이라 개발 환경이 곧 실행 환경이다 |
| 출시 범위 | 없음. 배포와 릴리스는 이 단계에 들어가지 않는다 |
| 외부 전송 | 없음. LLM은 모의 끝점으로 시험하고, 실제 끝점 확인은 저장소의 표본 코드로만 한다 |

## 표본

- `fixtures/shop` (새로 만든다): Java Spring 모양 저장소. 패키지 `order`, `coupon`, `payment`, `notification`, `config`. 진입점은 HTTP 3개(`POST /orders` 등), Kafka 리스너 1개, `@Scheduled` 1개, `main` 1개. 인터페이스와 구현 두 개, getter와 setter, 한 줄 위임, 테스트 클래스를 넣는다. Kotlin 파일 몇 개(데이터 클래스, 최상위 함수)도 넣는다.
- spring-petclinic, commons-lang: 측정과 수동 확인에만 쓴다. CI에서 내려받지 않는다.

## 인수조건

| 번호 | 내용 | 방법 | 단계 |
|---|---|---|---|
| B1 | `guide()`가 `fixtures/shop`의 패키지 5개, 클래스마다 역할(5.1 표), 클래스 사이 연결 수를 맞게 낸다. 테스트 클래스는 지도에 없다 | vitest | 7a |
| B2 | `POST /orders` 투어가 호출 순서대로 이어지고, 사소한 메서드는 접히며, 같은 메서드는 한 번만 단계가 되고, 인터페이스 호출은 구현 두 개로 갈린다 | vitest | 7a |
| B3 | 진입점 목록이 종류 순(HTTP, 메시지, 스케줄, main)이고 투어는 처음 열 때만 계산된다 | vitest | 7a |
| B4 | 진입점이 없는 표본(라이브러리 모양 작은 표본)에서 `noEntries`와 공개 API 투어가 나온다 | vitest | 7a |
| B5 | 생성 코드 경로와 `@Generated` 클래스를 넣지 않는다. 파일 3,000개 초과 판정이 맞다 | vitest | 7a |
| B6 | 비교 선택 화면의 "둘러보기"로 지금 브랜치를 열면 진행 단계가 보인 뒤 지도가 나온다 | Playwright | 7b |
| B7 | 지도에서 클래스를 고르면 연결 선과 맥락(부르는 쪽, 부르는 것, 진입점)이 보이고, "여기서 투어 시작"으로 그 진입점 투어가 열린다 | Playwright | 7b |
| B8 | 투어에서 `j`/`k`, `Enter`, `Backspace`가 1차와 같이 움직이고, 코드의 호출 줄 옆에 단계 번호가 보이며, "지도에서 보기"로 돌아간다 | Playwright | 7b |
| B9 | 앱을 다시 열면 같은 저장소의 마지막 보기(지도나 투어)와 위치가 돌아오고, 같은 커밋은 캐시로 바로 그린다 | Playwright | 7b |
| B10 | 900x600과 확대 150%에서 지도와 투어가 잘리거나 겹치지 않고, 키보드만으로 지도와 투어를 오갈 수 있다 | Playwright, 독립 검수 | 7b |
| B11 | "이 클래스 설명", "이 패키지 설명"은 미리보기 없이 보내지 않고, 패키지 설명에는 메서드 본문이 없다 | Playwright(모의 끝점) | 7c |

## 새 화면 독립 검수

1차 3단계, 5단계, 6단계와 같이 7b 화면(둘러보기 시작, 지도, 투어)을 새 검수 에이전트가 3회 본다. 회차마다 계획을 먼저 적고, 결과와 처리를 `ui-review.md`에 덧붙인다. 증적은 작성자의 증적 보관소로 옮기고 저장소에는 보관소 루트 기준 위치와 목록 해시만 남긴다.
