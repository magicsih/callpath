# 7b 새 화면 독립 검수 기록

테스트 계획의 "새 화면 독립 검수"에 따른 기록이다. 대상은 7b에서 새로 생긴 둘러보기 시작(비교 선택 화면 안), 지도, 투어 화면이다. 회차마다 시작 전에 계획을 적고, 끝난 뒤 결과와 처리를 덧붙인다. 스크린샷 원본은 작성자의 증적 보관소로 옮기고 여기에는 보관 경로와 해시만 남긴다.

## 1회차

### 계획 (시작 전)

- 대상: `718c58d` 빌드(`apps/desktop/out`)
- 환경: macOS 26.6 (Darwin 25.6), Electron 44.7.1, Node 24, 밝은 모드와 어두운 모드
- 격리 데이터: 실행마다 새 앱 데이터 폴더. 표본 저장소는 `fixtures/shop`을 커밋 하나로 둔 임시 git 저장소, 공개 저장소 spring-petclinic(진입점 18개)과 commons-lang(진입점 없음), 큰 저장소 판정을 볼 합성 저장소(Java 파일 3,200개, 모듈 4개)
- 외부 전송 없음: 네트워크로 보내는 기능은 이 화면에 없다. 정밀 분석은 끄고 띄운다(`CALLPATH_PRECISE=off`)
- 검수자: 구현자와 다른 검수 에이전트, 새 컨텍스트로 시작
- 확인할 기능: B6(진행 뒤 지도), B7(연결 선과 맥락, 여기서 투어 시작), B8(j/k, Enter, Backspace, 코드 옆 단계 번호, 지도에서 보기), B9(다시 열면 자리 복원, 같은 커밋은 캐시), B10(900x600과 150% 확대, 키보드만으로 지도와 투어 오가기), 큰 저장소에서 좁히기와 전체 둘러보기, 진입점이 없는 저장소의 공개 API 투어, 오류(없는 브랜치)
- 확인할 UX: 설계 3.3 화면별 기록의 목적과 가장 강조하는 행동, 처음 보는 저장소를 지도만 보고 이해할 수 있는지, 선과 칩 표시가 읽히는지, 투어 코드 옆 표시와 호출 스택이 따라가기 쉬운지
- 기대 결과: 기능 항목은 모두 재현되고, UX 문제는 화면, 재현 절차, 영향, 제안과 함께 보고된다
- 증거: 검수자가 직접 찍은 스크린샷과 실행 기록
