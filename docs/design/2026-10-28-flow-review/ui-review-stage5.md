# 5단계 새 화면 독립 검수 기록

테스트 계획의 "새 화면 독립 검수"에 따른 기록이다. 대상은 5단계에서 새로 생긴 연결 설정, PR 열기(시작 화면 주소 입력, 비교 선택 화면의 열린 PR 목록, 받는 중 화면), 메모, 게시 미리보기다. 회차마다 시작 전에 계획을 적고, 끝난 뒤 결과와 처리를 덧붙인다. 스크린샷 원본은 NAS로 옮기고 여기에는 위치와 해시만 남긴다.

## 1회차

### 계획 (시작 전)

- 대상: `29f283a` 빌드(`apps/desktop/out`)
- 환경: macOS 26 (Darwin 25.6), Electron 44.7.1, Node 24, 밝은 모드와 어두운 모드
- 격리 데이터: 쿠폰 표본으로 만든 임시 git 저장소, 실행마다 새 앱 데이터 폴더(`CALLPATH_USER_DATA`), E2E와 같은 모의 GitHub Enterprise 서버
- 외부 전송 없음: GitHub.com은 고르고 화면만 보며 저장하지 않는다(이 컴퓨터의 실제 gh 계정이 쓰이므로). 게시는 모의 서버에만 한다
- 검수자: 구현자와 다른 검수 에이전트, 새 컨텍스트로 시작
- 확인할 기능: A15 연결 저장과 실패 원인, PR 열기(연결 없음 안내, 받는 중 단계, 실패와 다시 시도, 다시 열기 복원), 열린 PR 목록, A16 메모, A17 게시 미리보기와 게시, 900x600과 150% 확대, 키보드만으로 메모와 게시
- 확인할 UX: 설계 3.7 화면별 목적과 가장 강조하는 행동, 줄 코멘트와 일반 코멘트의 구분이 미리보기에서 분명한지, 이전 커밋 메모 안내, 토큰 안내 문구
- 기대 결과: 기능 항목은 모두 재현되고, UX 문제는 화면, 재현 절차, 영향, 제안과 함께 보고된다
- 증거: 검수자가 직접 찍은 스크린샷과 실행 기록

### 결과

기능 중 A15 연결 설정, PR 열기, A16 메모, A17 게시는 통과했다. 크기 조건과 키보드 조건은 부분 실패였다. 중요 3건, 개선 8건이 나왔고 모두 받아들여 고쳤다. 검수자는 64장을 찍었고, 모의 서버에 올라간 4건의 본문이 미리보기와 글자 단위로 같았다. 명암비는 두 모드 모두 최저 4.55:1이었다.

| 번호 | 심각도 | 지적 | 처리 |
|---|---|---|---|
| 1 | 중요 | m으로 작성 칸을 열었다 닫은 뒤 다시 분석하면 작성 칸이 저절로 열리고 j가 칸에 입력됨 | 상세 영역이 새로 그려져도 이미 처리한 요청은 다시 열지 않음. A16에서 확인 |
| 2 | 중요 | 게시 미리보기에서 Tab이 대화상자 밖으로 나가고, 열린 채 j를 누르면 뒤 화면이 이동 | 기본 모달 대화상자(`showModal`)로 바꿔 밖을 막고 Esc를 받음. 열린 동안 리뷰 단축키를 멈춤. A17에서 Tab 4번과 j, Esc 확인 |
| 3 | 중요 | PR 모드 상단 바가 900x600, 1280x800 150%, 900x600 150%에서 넘쳐 "다시 분석"이 화면 밖 | 넘치면 버튼을 다음 줄로 보냄. 1100px 아래에서는 분석 요약을 숨기고, 760px 아래에서는 앱 이름을 숨기고 간격을 줄임. 세 크기에서 버튼이 창 안에 있고 코드 줄이 보이는지 E2E로 확인 |
| 4 | 개선 | 메모 저장, 서랍 Esc, 대화상자 닫기, 연결 저장 뒤 초점이 사라짐 | 메모 저장과 취소는 편집기로, 서랍은 "메모" 버튼으로, 대화상자는 연 버튼으로, 연결 저장은 결과 문구로, 실패는 고칠 입력칸으로 초점을 돌림 |
| 5 | 개선 | 호스트에 닿지 않아도 토큰을 지우고 원문 오류만 보임 | 닿지 않는 경우는 토큰을 남기고 "주소와 포트, 사내망(VPN)" 안내, 토큰 거부는 권한과 만료일 안내. A15에서 확인 |
| 6 | 개선 | PR 오류에서 연결 설정으로 가면 기본값으로 열림 | PR 주소 모양으로 제공자와 호스트를 채움. 비교 화면의 연결 안내는 원격 주소로 채우고, 제공자를 모르면 채우지 않음 |
| 7 | 개선 | 서랍에서 메모를 눌러 이동하면 서랍이 코드를 덮고, 목록이 파일 경로 순서 | 이동하면 서랍을 닫고 그 줄을 강조함. 목록은 흐름 순서. A16에서 강조 줄 확인 |
| 8 | 개선 | 줄 옆 연필 표시가 작고 연하며, 작성 중 대상 줄이 강조되지 않음 | 표시를 15px 굵게, 두 모드 모두 대비가 높은 색으로. 작성 칸을 열면 그 줄을 강조 |
| 9 | 개선 | 형식이 틀린 PR 주소에도 "다시 시도"가 나옴 | 시작 화면으로 돌아가 입력을 남긴 채 입력 아래에 원인을 보임 |
| 10 | 개선 | 미리보기 첫 초점이 "게시", 올릴 저장소와 호스트가 없음, 완료 뒤 링크 없음 | 첫 초점은 취소. 호스트와 저장소를 함께 보임. 올라간 코멘트마다 "코멘트 열기" |
| 11 | 개선 | 오른쪽 클릭 메뉴의 영어 "Copy", 입력 안내가 입력에 묶이지 않음, 게시됨 버튼 이름, 같은 줄 메모의 지우기 이름 중복, 지우기 확인 없음 | Monaco 한국어 문구를 불러옴. 안내를 `aria-describedby`로 묶음. 버튼 이름에 브라우저로 연다는 말과 메모 앞부분을 넣음. 메모와 연결 지우기는 한 번 더 확인 |

같은 회차에 로컬 리뷰 1회차 지적 4건도 고쳤다: 다른 단계의 메모로 갈 때 강조가 지워지던 효과 순서, 메모 저장과 게시의 오류를 결과로 돌려 대화상자가 닫히지 않던 문제, 다른 비교의 메모가 같은 커밋이면 섞이던 조회 조건, http 주소를 열지 않던 외부 링크. Linux CI에서 암호 저장소가 없어 연결 저장이 실패하던 문제도 같은 회차에 고쳤다(설계 3.7).

## 2회차

### 계획 (시작 전)

- 대상: `e4be486` 빌드(`apps/desktop/out`)
- 환경, 격리 데이터, 외부 전송 없음: 1회차와 같음
- 검수자: 새 검수 에이전트. 앞 회차 결론은 전달하지 않는다
- 확인할 기능과 UX: 1회차와 같은 범위 전체. 1회차에서 고친 부분(키보드와 초점, 좁은 창 상단 바, 서랍 이동, 연결 실패 안내)이 다른 화면을 깨지 않았는지 함께 본다
- 기대 결과, 증거: 1회차와 같음

### 결과

1회차에서 고친 키보드와 초점, 좁은 창 상단 바, 연결 실패 안내, 틀린 PR 주소, 게시 일부 실패와 다시 올리기는 통과했다. 중요 3건, 개선 9건이 새로 나왔고 모두 받아들여 고쳤다. 검수자는 79장을 찍었다. PR에 새 커밋이 왔을 때의 이전 커밋 메모는 모의 서버를 다시 띄우면 PR 주소의 포트가 바뀌어 확인하지 못했다(로컬 비교로는 통과). 검수자가 처음 띄운 앱이 정밀 분석용 JDT LS를 공식 배포처에서 내려받았다(앱의 기본 동작, 보낸 데이터 없음). 받은 캐시는 검수자가 지웠고, 3회차는 정밀 분석을 끄고 띄운다.

| 번호 | 심각도 | 지적 | 처리 |
|---|---|---|---|
| 1 | 중요 | 왼쪽(바뀌기 전) 줄을 고르고 m을 누르면 안내 없이 메서드 첫 줄에 메모가 열림 | 왼쪽 줄을 고른 채 m을 누르면 남길 수 없다고 알리고 작성 칸을 열지 않음. 작성 칸 안내도 "오른쪽(변경 후) 코드"로 고침. A16에서 확인 |
| 2 | 중요 | 서랍이 열린 채로 상세 머리, 작성 칸, 코드를 덮음 | 넓은 창에서는 서랍이 호출 스택 자리에 들어가 코드를 덮지 않음. 좁은 창에서는 가운데 위에 뜨고 뒤를 눌러 닫음. 작성 칸을 열면 서랍을 닫음. A16에서 위치 확인 |
| 3 | 중요 | 서랍 밖에 초점이 있으면 Esc로 닫히지 않음, 서랍에서 j가 뒤 단계를 바꾸고, Tab이 가려진 링크로 감 | Esc는 어디서든 서랍을 닫음. 서랍 안에서는 단계 이동 키를 쓰지 않음. 좁은 창에서 서랍이 열린 동안 뒤 영역을 `inert`로 막음 |
| 4 | 개선 | 게시 미리보기를 만들지 못하면 취소만 있음 | "다시 시도"와 원인별 다음 행동 안내. 올리다 통째로 실패한 경우도 같은 메모로 다시 시도 |
| 5 | 개선 | 답하지 않는 호스트에서 "확인 중"만 29초, 영문 원문 오류 | 경과 시간과 "최대 30초", "확인 멈추기"(멈춘 확인은 저장하지 않음). 연결 거부, 이름 없음, 시간 초과, 인증서, 막힌 포트를 한국어 이유로. 서버가 준 영문 문구는 "서버 응답:" 뒤에 따로 둠 |
| 6 | 개선 | gh CLI 방식은 어떤 계정이 쓰일지 저장 전에 알 수 없음 | gh 설정에서 계정 이름을 읽어(네트워크 없음) 선택지와 안내 문구에 보임 |
| 7 | 개선 | 줄 옆 메모 표시가 작고, 본문과 읽기용 이름이 없음 | 표시에 마우스를 올리면 본문을 보임. 상세 머리에 "✎ 메모 N" 칩을 두고 줄 번호를 이름에 넣음. 칩을 누르면 서랍이 열림 |
| 8 | 개선 | 연결 설정에 들어올 때와 연결을 지운 뒤 초점이 사라짐 | 들어오면 제목, 지운 뒤에는 연결 목록 제목으로 초점 |
| 9 | 개선 | 이전 커밋 메모만 있으면 "메모 0"으로 보임 | "메모 0 이전 1"로 보이고 읽기용 이름에 두 수를 함께 적음 |
| 10 | 개선 | 게시된 메모의 링크 버튼 이름이 모두 같고, 지울 때 PR 코멘트가 어떻게 되는지 말하지 않음 | 버튼 이름에 위치와 메모 앞부분. 게시된 메모를 지울 때 "앱의 메모만 지웁니다. PR 코멘트는 남습니다" |
| 11 | 개선 | 작은 창에서 메모가 많으면 게시 버튼이 목록 아래로 밀리고, 결과 문구가 버튼 아래 | 목록만 스크롤하고 버튼 줄은 고정. 결과 문구는 버튼 위 |
| 12 | 개선 | 제공자를 바꾸면 채워 둔 호스트가 지워지고, PR에서 온 "돌아가기"가 무엇을 하는지 알 수 없음 | 기본값이 아니면 호스트를 남김. PR 열기에서 왔으면 "돌아가서 PR 다시 열기" |

같은 회차에 로컬 리뷰 2회차 지적 3건도 고쳤다: 개발 모드(StrictMode)에서 대화상자를 두 번 여는 예외, 서랍에서 이동한 뒤 초점이 사라지는 문제(목록의 그 항목으로), 메모 읽기와 지우기 실패가 조용히 묻히는 문제(서랍에 이유).

## 3회차

### 계획 (시작 전)

- 대상: `8c33f3a` 빌드(`apps/desktop/out`)
- 환경, 격리 데이터, 외부 전송 없음: 1회차와 같음. 정밀 분석은 끄고 띄운다(`CALLPATH_PRECISE=off`)
- 검수자: 새 검수 에이전트. 앞 회차 결론은 전달하지 않는다
- 확인할 기능과 UX: 1회차와 같은 범위 전체. 서랍의 두 모양(넓은 창의 옆 영역, 좁은 창의 띄운 서랍), 연결 확인 멈추기, 왼쪽 줄 메모 안내를 함께 본다
- 기대 결과, 증거: 1회차와 같음

### 결과

차단은 없었다. A15, PR 열기(형식 오류, 연결 없음, 받는 중, 실패와 다시 시도, 복원, 열린 PR 목록), A16, A17(미리보기 실패와 일부 실패에서 다시 시도 포함), 서랍 위치, 키보드와 화면 읽기는 통과했다. 900x600과 150%에서 작성 칸 버튼이 잘려 크기 조건은 실패였다. 중요 3건, 개선 5건이 나왔고 모두 받아들여 고쳤다. 검수자는 120장을 찍었고, 올라간 코멘트 5건의 본문이 미리보기와 글자 단위로 같았다. 정밀 분석은 꺼서 외부에서 받은 것은 없다.

검수 도중 구현자가 18시 52분부터 54분까지 약 2분 동안 `apps/desktop/out`을 다른 빌드로 바꿨다가 `8c33f3a` 소스로 다시 빌드했다. 바뀐 빌드의 차이는 항목을 옮길 때 편집기가 초점을 가져가지 않게 한 한 가지다. 그 사이 검수자가 앱을 새로 띄웠다면 이 동작만 달랐다. 발견 8건 중 이 동작과 관련된 것은 없다.

| 번호 | 심각도 | 지적 | 처리 |
|---|---|---|---|
| 1 | 중요 | 취소한 초안이 다음 작성 칸에 남아, 합쳐진 본문이 실제로 올라감 | 취소하면 초안과 오류를 비움. A16에서 확인 |
| 2 | 중요 | 900x600, 150%에서 "메모 저장"이 두 줄, "취소"가 "취/소"로 쪼개지고, 둘을 함께 걸면 잘림 | 버튼은 줄어들거나 줄바꿈하지 않고, 안내 문구는 다음 줄로. 좁은 창 E2E에서 버튼 높이 확인 |
