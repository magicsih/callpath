# 5단계 새 화면 독립 검수 기록

테스트 계획의 "새 화면 독립 검수"에 따른 기록이다. 대상은 5단계에서 새로 생긴 연결 설정, PR 열기(시작 화면 주소 입력, 비교 선택 화면의 열린 PR 목록, 받는 중 화면), 메모, 게시 미리보기다. 회차마다 시작 전에 계획을 적고, 끝난 뒤 결과와 처리를 덧붙인다. 스크린샷 원본은 NAS로 옮기고 여기에는 위치와 해시만 남긴다.

## 1회차

### 계획 (시작 전)

- 대상: `29f283a` 빌드(`apps/desktop/out`)
- 환경: macOS 26 (Darwin 25.6), Electron 44.7.1, Node 24, 밝은 모드와 어두운 모드
- 격리 데이터: 쿠폰 표본으로 만든 임시 git 저장소, 실행마다 새 앱 데이터 폴더(`CALLPATH_USER_DATA`), E2E와 같은 모의 GitHub Enterprise 서버
- 외부 전송 없음: GitHub.com은 고르고 화면만 보며 저장하지 않는다(이 컴퓨터의 실제 gh 계정이 쓰이므로). 게시는 모의 서버에만 한다
- 검수자: 구현자와 다른 검수 에이전트, 새 컨텍스트로 시작
- 확인할 기능: A15 연결 저장과 실패 원인, PR 열기(연결 없음 안내, 받는 중 단계, 실패와 다시 시도, 다시 열기 복원), 열린 PR 목록, A16 메모, A17 게시 미리보기와 게시, 900x600과 150% 확대, 키보드만으로 메모와 게시
- 확인할 UX: 설계 3.7 화면별 목적과 가장 강조하는 행동, 줄 코멘트와 일반 코멘트의 구분이 미리보기에서 분명한지, 이전 커밋 메모 안내, 토큰 안내 문구
- 기대 결과: 기능 항목은 모두 재현되고, UX 문제는 화면, 재현 절차, 영향, 제안과 함께 보고된다
- 증거: 검수자가 직접 찍은 스크린샷과 실행 기록

### 결과

기능 중 A15 연결 설정, PR 열기, A16 메모, A17 게시는 통과했다. 크기 조건과 키보드 조건은 부분 실패였다. 중요 3건, 개선 8건이 나왔고 모두 받아들여 고쳤다. 검수자는 64장을 찍었고, 모의 서버에 올라간 4건의 본문이 미리보기와 글자 단위로 같았다. 명암비는 두 모드 모두 최저 4.55:1이었다.

| 번호 | 심각도 | 지적 | 처리 |
|---|---|---|---|
| 1 | 중요 | m으로 작성 칸을 열었다 닫은 뒤 다시 분석하면 작성 칸이 저절로 열리고 j가 칸에 입력됨 | 상세 영역이 새로 그려져도 이미 처리한 요청은 다시 열지 않음. A16에서 확인 |
| 2 | 중요 | 게시 미리보기에서 Tab이 대화상자 밖으로 나가고, 열린 채 j를 누르면 뒤 화면이 이동 | 기본 모달 대화상자(`showModal`)로 바꿔 밖을 막고 Esc를 받음. 열린 동안 리뷰 단축키를 멈춤. A17에서 Tab 4번과 j, Esc 확인 |
| 3 | 중요 | PR 모드 상단 바가 900x600, 1280x800 150%, 900x600 150%에서 넘쳐 "다시 분석"이 화면 밖 | 넘치면 버튼을 다음 줄로 보냄. 1100px 아래에서는 분석 요약을 숨기고, 760px 아래에서는 앱 이름을 숨기고 간격을 줄임. 세 크기에서 버튼이 창 안에 있고 코드 줄이 보이는지 E2E로 확인 |
| 4 | 개선 | 메모 저장, 서랍 Esc, 대화상자 닫기, 연결 저장 뒤 초점이 사라짐 | 메모 저장과 취소는 편집기로, 서랍은 "메모" 버튼으로, 대화상자는 연 버튼으로, 연결 저장은 결과 문구로, 실패는 고칠 입력칸으로 초점을 돌림 |
| 5 | 개선 | 호스트에 닿지 않아도 토큰을 지우고 원문 오류만 보임 | 닿지 않는 경우는 토큰을 남기고 "주소와 포트, 사내망(VPN)" 안내, 토큰 거부는 권한과 만료일 안내. A15에서 확인 |
| 6 | 개선 | PR 오류에서 연결 설정으로 가면 기본값으로 열림 | PR 주소 모양으로 제공자와 호스트를 채움. 비교 화면의 연결 안내는 원격 주소로 채우고, 제공자를 모르면 채우지 않음 |
| 7 | 개선 | 서랍에서 메모를 눌러 이동하면 서랍이 코드를 덮고, 목록이 파일 경로 순서 | 이동하면 서랍을 닫고 그 줄을 강조함. 목록은 흐름 순서. A16에서 강조 줄 확인 |
| 8 | 개선 | 줄 옆 연필 표시가 작고 연하며, 작성 중 대상 줄이 강조되지 않음 | 표시를 15px 굵게, 두 모드 모두 대비가 높은 색으로. 작성 칸을 열면 그 줄을 강조 |
| 9 | 개선 | 형식이 틀린 PR 주소에도 "다시 시도"가 나옴 | 시작 화면으로 돌아가 입력을 남긴 채 입력 아래에 원인을 보임 |
| 10 | 개선 | 미리보기 첫 초점이 "게시", 올릴 저장소와 호스트가 없음, 완료 뒤 링크 없음 | 첫 초점은 취소. 호스트와 저장소를 함께 보임. 올라간 코멘트마다 "코멘트 열기" |
| 11 | 개선 | 오른쪽 클릭 메뉴의 영어 "Copy", 입력 안내가 입력에 묶이지 않음, 게시됨 버튼 이름, 같은 줄 메모의 지우기 이름 중복, 지우기 확인 없음 | Monaco 한국어 문구를 불러옴. 안내를 `aria-describedby`로 묶음. 버튼 이름에 브라우저로 연다는 말과 메모 앞부분을 넣음. 메모와 연결 지우기는 한 번 더 확인 |

같은 회차에 로컬 리뷰 1회차 지적 4건도 고쳤다: 다른 단계의 메모로 갈 때 강조가 지워지던 효과 순서, 메모 저장과 게시의 오류를 결과로 돌려 대화상자가 닫히지 않던 문제, 다른 비교의 메모가 같은 커밋이면 섞이던 조회 조건, http 주소를 열지 않던 외부 링크. Linux CI에서 암호 저장소가 없어 연결 저장이 실패하던 문제도 같은 회차에 고쳤다(설계 3.7).

## 2회차

### 계획 (시작 전)

- 대상: 1회차 처리를 반영한 빌드(`apps/desktop/out`, 커밋은 시작 시 기록)
- 환경, 격리 데이터, 외부 전송 없음: 1회차와 같음
- 검수자: 새 검수 에이전트. 앞 회차 결론은 전달하지 않는다
- 확인할 기능과 UX: 1회차와 같은 범위 전체. 1회차에서 고친 부분(키보드와 초점, 좁은 창 상단 바, 서랍 이동, 연결 실패 안내)이 다른 화면을 깨지 않았는지 함께 본다
- 기대 결과, 증거: 1회차와 같음
