# 6단계 새 화면 독립 검수 기록

테스트 계획의 "새 화면 독립 검수"에 따른 기록이다. 대상은 6단계에서 새로 생긴 LLM 설정 화면과 설명 대화상자, 그리고 리뷰 화면의 LLM 버튼 자리다. 회차마다 시작 전에 계획을 적고, 끝난 뒤 결과와 처리를 덧붙인다. 스크린샷 원본은 NAS로 옮기고 여기에는 위치와 해시만 남긴다.

## 1회차

### 계획 (시작 전)

- 대상: `de99038` 빌드(`apps/desktop/out`)
- 환경: macOS 26 (Darwin 25.6), Electron 44.7.1, Node 24, 밝은 모드와 어두운 모드
- 격리 데이터: 쿠폰 표본으로 만든 임시 git 저장소, 실행마다 새 앱 데이터 폴더, 모의 OpenAI 호환 끝점(정상, 키 거부, 서버 오류, 무응답, 한 번에 답, 느린 답, 모델 목록 없음)
- 외부 전송 없음: 실제 LLM 끝점에는 보내지 않는다. 정밀 분석은 끄고 띄운다(`CALLPATH_PRECISE=off`)
- 검수자: 구현자와 다른 검수 에이전트, 새 컨텍스트로 시작
- 확인할 기능: A10(미리보기 없이 전송하지 않음, 보낸 내용이 기록에 남음), 설정 저장과 확인, 키를 다시 보이지 않음, 답 받기와 멈추기, 지난 답, 오류 안내, 900x600과 150% 확대, 키보드만으로 설정부터 답 읽기까지
- 확인할 UX: 설계 3.4, 3.8의 목적과 가장 강조하는 행동, 무엇이 어디로 나가는지 이해되는지, 미리보기 정보량, 답 읽기 편의
- 기대 결과: 기능 항목은 모두 재현되고, UX 문제는 화면, 재현 절차, 영향, 제안과 함께 보고된다
- 증거: 검수자가 직접 찍은 스크린샷과 실행 기록

### 결과

차단은 없었다. A10의 세 조건(미리보기를 취소하면 대화 요청 0건, 보낸 본문이 "보낼 메시지 전체"와 글자 단위로 같음, 같은 id로 sent와 done 두 줄이 남고 키와 헤더 값이 없음)은 흐름 요약과 메서드 설명 모두 통과했다. 설정 저장과 확인, 키 다시 보이지 않음, 멈추기, 오류 안내, 키보드, 크기 조건도 통과했다. 받은 답 다시 보기와 진입점 미확정 항목은 실패였다. 중요 2건, 개선 6건(문구 5가지 포함)이 나왔고 모두 받아들여 고쳤다. 검수자는 97장을 찍었다. 회색 글씨 대비는 밝은 모드 5.48:1, 어두운 모드 5.98:1 이상이었다.

| 번호 | 심각도 | 지적 | 처리 |
|---|---|---|---|
| 1 | 중요 | 설정을 다녀오면 받은 답이 사라져 다시 받으려면 코드를 또 보내야 함 | 받은 답을 리뷰 화면 밖(앱)에 커밋 SHA 키로 둠. A10에서 설정을 다녀온 뒤 "(받음)" 확인 |
| 2 | 중요 | 진입점 미확정 단계의 메서드 설명에 "호출 경로: 이 메서드가 진입점"을 보냄 | "진입점에서 닿는 호출을 찾지 못했습니다(진입점 미확정)"로 보냄. 단위 테스트와 A10에서 확인 |
| 3 | 개선 | 목록에 없는 모델이나 모델 목록 없음 안내가 성공 문구 옆 회색 글씨 | 성공 문구 아래 줄에 경고 색과 아이콘으로 |
| 4 | 개선 | 900x600, 150%에서 첫 초점의 취소 버튼이 화면 밖, 메시지를 펼치면 보내기가 밀림 | 내용만 스크롤하고 버튼 줄은 대화상자 아래에 고정 |
| 5 | 개선 | 테스트 항목에서 "이 메서드 설명"이 무엇을 설명하는지 알 수 없음 | 버튼에 대상 이름(예: "OrderService.placeOrder 설명", "POST /orders 흐름 요약") |
| 6 | 개선 | 메서드 밖 변경에서 버튼이 꺼진 이유가 없음 | 쓸 수 없는 버튼은 숨기고 이유를 글로 보임(메서드 밖 변경, 진입점 미확정) |
| 7 | 개선 | 켜져 있으면 리뷰 화면에서 설정으로 갈 길이 없음 | 버튼 아래에 "LLM 설정" 링크 |
| 8 | 개선 | 오류 때 제목이 "메서드 설명"으로 바뀜, 보낼 곳 문구 칸 벌어짐, 뺀 곳을 알리지 않음, 키 거부 뒤 초점이 주소 칸, 어두운 모드 헤더 칸 배경 | 대상 제목 유지, 문구를 한 덩어리로, 뺀 범위 목록, 키 거부면 키 칸으로 초점, 입력칸과 같은 스타일 |

검수자가 추측으로 남긴 "실제 LLM은 마크다운으로 답해 기호가 그대로 보일 것"도 받아들였다. 제목, 목록, 코드 블록, 굵게, 줄 안 코드만 React 요소로 보인다(HTML로 넣지 않는다). A10의 모의 답에 마크다운을 넣어 확인했다.

같은 회차에 로컬 리뷰 1회차 지적 4건도 고쳤다: 모델 목록 미지원을 404 말고 405, 501도 같이 처리, 미리보기 30분 만료를 보낼 때 검사, 닫은 미리보기를 바로 버리고 키는 보낼 때만 풂, 글자 상한은 흐름 뒤쪽부터 빼고 첫 조각 하나가 넘으면 앞부분만.

## 2회차

### 계획 (시작 전)

- 대상: `d10db21` 빌드(`apps/desktop/out`)
- 환경, 격리 데이터, 외부 전송 없음: 1회차와 같음
- 검수자: 새 검수 에이전트. 앞 회차 결론은 전달하지 않는다
- 확인할 기능과 UX: 1회차와 같은 범위 전체. 답의 마크다운 표시, 버튼 이름과 꺼진 이유, 고정한 버튼 줄을 함께 본다
- 기대 결과, 증거: 1회차와 같음

### 결과

A10, 설정 저장과 확인, 키와 헤더 보호, 멈추기와 지난 답(설정, 다른 단계, 저장소를 다시 연 뒤에도), 오류 안내, 키보드는 통과했다. 크기 조건은 미리보기 때문에 실패였다. 차단 1건, 중요 3건, 개선 4건(문구와 배치 6가지 포함)이 나왔고 모두 받아들여 고쳤다. 검수자는 58장을 찍었다.

| 번호 | 심각도 | 지적 | 처리 |
|---|---|---|---|
| 1 | 차단 | 미리보기가 창보다 길면 마우스로 스크롤되지 않아 "보내기"에 닿지 못함 | 원인은 5단계 게시 대화상자용 `flex: none` 규칙이 이 대화상자 본문에도 걸린 것. 목록과 본문만 줄어들며 스크롤하고 버튼 줄은 고정. A10에서 메시지를 펼치고 휠로 스크롤한 뒤 보내기가 창 안에 있는지 확인 |
| 2 | 중요 | 메서드 설명 요약에 "시그니처도 바뀜"이 빠짐 | 흐름 요약과 같은 표기. 단위 테스트 |
| 3 | 중요 | 같은 호출 460번이 그대로 나가 요약이 3만 자를 넘음 | 연달은 같은 호출은 "append ×460", 목록은 이름별 횟수로 묶음. 요약은 4천 자 상한을 따로 둠. 단위 테스트 |
| 4 | 개선 | 메서드 안쪽을 자른 사실과 뺀 조각의 메서드 이름이 미리보기에 없음 | 범위마다 메서드 이름, 자른 조각은 "메서드는 N줄까지이지만 M줄까지만 보냅니다". 메서드 설명에서는 "흐름 뒤쪽"이라 부르지 않음 |
| 5 | 중요 | 새 헤더만 넣으면 저장된 헤더가 경고 없이 모두 바뀜 | 바뀐다는 경고와 저장된 헤더 이름을 보임. E2E로 확인 |
| 6 | 개선 | 좁은 창에서 켜진 뒤 설정으로 가는 길이 없음, "꺼져 있습니다"가 무엇인지 없음, 저장하지 않은 변경을 말없이 버림 | 좁은 창 버튼 옆에도 "LLM 설정", "LLM 설명이 꺼져 있습니다", 돌아갈 때 저장하지 않은 변경을 버릴지 물음. E2E로 확인 |
| 7 | 개선 | 답의 코드 블록과 보낼 메시지가 고정폭이 아님, 기울임과 표와 인용이 원문 그대로 | 게시 대화상자에만 본문 글꼴을 쓰게 범위를 좁힘. 기울임, 인용을 표시하고 표는 칸을 맞춘 고정폭 글로 |
| 8 | 개선 | 500에서 안내 중복, "(받음)" 줄 깨짐, 생성자 제목 불일치, 기다리는 시간과 보낸 곳이 안 보임, 저장 못 하는 이유 없음, 테스트 항목 안내 없음 | 오류 문구에 다음 행동이 있으면 덧붙이지 않음, 낱말 단위 줄바꿈, 이름 표기를 코어 한 곳으로 모아 화면과 LLM 내용이 같은 이름을 씀, 경과 초와 60초 한도와 "어디의 답"을 보임, "저장하려면 …를 넣으세요", 테스트를 보고 있으면 테스트 코드는 보내지 않는다고 안내 |

같은 회차에 로컬 리뷰 2회차 지적 2건도 고쳤다: 첫 조각을 자를 때 생략 안내까지 넣은 최종 길이로 상한을 지키고 한 줄이 너무 길면 글자로 자름, 대화상자 제목을 화면 표기와 맞춤(위 8번과 같은 수정).

## 3회차

### 계획 (시작 전)

- 대상: `d263aa4` 빌드(`apps/desktop/out`)
- 환경, 격리 데이터, 외부 전송 없음: 1회차와 같음
- 검수자: 새 검수 에이전트. 앞 회차 결론은 전달하지 않는다
- 확인할 기능과 UX: 1회차와 같은 범위 전체. 긴 미리보기와 긴 답의 스크롤, 설정의 저장하지 않은 변경, 큰 메서드의 글자 상한 안내를 함께 본다
- 기대 결과, 증거: 1회차와 같음

### 결과

차단은 없었다. 기능 항목은 모두 통과했다(A10 세 조건, 설정 저장과 보호, 답 받기와 마크다운, 오류 안내, 단계와 테스트와 진입점 미확정과 메서드 밖, 글자 상한, 크기 조건에서 휠과 키보드로 버튼에 닿음, 키보드와 읽기용 이름). 중요 1건, 개선 6건이 나왔고 모두 받아들여 고쳤다. 검수자는 96장을 찍었고, 보낸 본문 17건이 모두 미리보기와 같았다. 미리보기 30분 만료, 앞 흐름에서 이미 나온 단계를 빼는 규칙(표본에 흐름이 하나뿐), VoiceOver 실제 낭독은 확인하지 못했다.

| 번호 | 심각도 | 지적 | 처리 |
|---|---|---|---|
| 1 | 중요 | 긴 답을 받는 중에 위로 올려 읽으면 새 조각마다 맨 아래로 끌려 내려감 | 맨 아래에 있을 때만 따라 내려감 |
| 2 | 개선 | 변경 후 코드가 혼자 상한을 넘으면 변경 전 코드(3줄)를 통째로 빼 비교할 수 없음 | 메서드 설명은 변경 전 자리(최대 절반)를 먼저 남기고 변경 후를 자름. 단위 테스트 |
| 3 | 개선 | LLM 설정을 다녀오면 코드 스크롤이 처음으로 돌아감 | 설정 동안 리뷰 화면을 숨긴 채 그대로 둠. 분석도 다시 돌지 않음. 돌아오면 설정을 다시 읽음. 같은 줄이 보이는지 직접 확인 |
| 4 | 개선 | "(받음)"의 괄호가 다른 줄로 갈라짐 | 한 덩어리로 묶어 줄바꿈하지 않음 |
| 5 | 개선 | 저장하지 않고 떠날 때 확인에서 초점이 "버리고 돌아가기"에 먼저, Esc 안 됨, 계속 고치기 뒤 초점 사라짐 | 초점은 "계속 고치기"에 먼저, Esc는 계속 고치기, 닫히면 돌아가기 버튼으로. E2E로 확인 |

| 7 | 개선 | 보내는 요약에 "OrderService.OrderService", 바뀌지 않은 진입점에 "변경 후" | 이름은 화면 표기에 패키지와 클래스를 덧붙임, 바뀌지 않은 메서드는 "바뀌지 않음" |

## 마무리

- 3회 모두 계획을 먼저 적고, 새 검수 에이전트가 앞 회차 결론 없이 실제 실행 화면으로 판정했다. 발견은 1회차 8건, 2회차 8건(차단 1건), 3회차 7건이고 모두 반영했다.
- 3회차 처리 뒤의 4회차 검수는 계획에 없어 돌리지 않았다. 3회차 처리는 E2E와 직접 측정으로 확인했다.
- 실제 외부 LLM 끝점으로는 보내지 않았다. 모든 검수와 E2E는 모의 OpenAI 호환 끝점으로 했다.
