# 3단계 새 화면 독립 검수 기록

테스트 계획의 "새 화면 독립 검수"에 따른 기록이다. 회차마다 시작 전에 계획을 적고, 끝난 뒤 결과와 처리를 덧붙인다. 스크린샷 원본은 NAS로 옮기고 여기에는 위치와 해시만 남긴다.

## 1회차

### 계획 (시작 전)

- 대상: `fe302df` 빌드(`apps/desktop/out`)
- 환경: macOS 26 (Darwin 25.6), Electron 44.7.1, Node 24, 화면 밝은 모드
- 격리 데이터: 쿠폰 표본(Java, Kotlin)으로 만든 임시 git 저장소, 실행마다 새 앱 데이터 폴더(`CALLPATH_USER_DATA`)
- 검수자: 구현자와 다른 검수 에이전트, 새 컨텍스트로 시작
- 확인할 기능: A5 테스트 토글, A6 단계 이동과 위치, A7 다시 열기 복원, A12 상태별 화면, A13 900x600과 150% 확대, A14 키보드만으로 처음부터 끝까지, 화면 읽기용 이름
- 확인할 UX: 설계 3.6 화면별 목적과 가장 강조하는 행동, 정보량, 상태 표현, 아이콘과 라벨, 쿠폰 예시의 "재고 차감이 결제 앞으로 이동"을 첫 흐름에서 알아챌 수 있는지
- 기대 결과: 기능 항목은 모두 재현되고, UX 문제는 화면, 재현 절차, 영향, 제안과 함께 보고된다
- 증거: 검수자가 직접 찍은 스크린샷과 실행 기록

### 결과

기능 A5, A6, A7, A12, A13, A14는 모두 통과했다. 차단 0건, 중요 2건, 개선 9건이 나왔고 모두 받아들여 고쳤다. 검수 중 구현자가 상태 저장과 워커 종료 처리를 고친 코드는 빌드에 반영되지 않은 상태였으므로 A7은 2회차에서 다시 본다.

| 번호 | 심각도 | 지적 | 처리 |
|---|---|---|---|
| 1 | 중요 | diff 줄 번호 옆이 네모 문자로 보임 | Monaco 아이콘 글꼴과 diff 기여 모듈을 번들에 넣음. E2E에서 글꼴 로드 확인 |
| 2 | 중요 | 어두운 모드 주 버튼 대비 3.16:1 | 주 버튼 배경 토큰(`--accent-strong`)을 따로 두어 4.5:1 이상 |
| 3 | 개선 | 브랜치를 못 찾은 실패인데 주 버튼이 다시 분석 | 오류 종류를 나눠 비교를 바꿔야 하는 실패는 비교 바꾸기가 주 버튼 |
| 4 | 개선 | 없는 경로와 파일 경로도 "Git 저장소가 아닙니다" | 경로 없음, 파일 경로, 저장소 아님을 나눠 안내 |
| 5 | 개선 | 커밋 없는 저장소에서 이유 없이 분석 버튼이 꺼짐 | "비교할 브랜치가 없습니다" 안내와 다시 읽기 |
| 6 | 개선 | 긴 이름이 잘리고 툴팁이 없음 | 목록, 호출 스택, 이어지는 단계에 전체 이름 툴팁. 테스트 이름은 두 줄까지 |
| 7 | 개선 | 바뀌지 않은 진입점에 빗금, 추가 메서드 왼쪽에 빈 빨간 줄 | 한쪽만 있는 코드는 diff 대신 한 칸 보기(추가는 초록, 삭제는 빨강) |
| 8 | 개선 | 900x600과 150% 동시 적용에서 diff가 4줄 | 좁은 창에서는 오른쪽 영역을 숨기고 가운데 위에 호출 경로 한 줄 |
| 9 | 개선 | 다음 단계 버튼이 다른 버튼과 같은 모양 | 다음 버튼을 주 버튼으로 |
| 10 | 개선 | 체크박스 초점에서 t 무시, 이동 중 "no diff result available" 오류 | 체크박스에서도 t 동작. diff 모델을 한 쌍만 두고 내용만 바꿔 오류 제거. E2E에서 페이지 오류 0건 확인 |
| 11 | 개선 | "main와 main", 헤더 "진입점 2", 생성자가 "OrderService OrderService" | 조사 없는 문구로 바꿈, 헤더는 흐름 수와 바뀐 메서드 수, 생성자는 "생성자"로 표시 |

검수자 제안 중 흐름 제목에 순서 변경 수를 붙이는 것과 줄 강조를 진하게 하는 것도 반영했다.

## 2회차

### 계획 (시작 전)

- 대상: 1회차 지적을 고친 빌드(아래 커밋)
- 환경, 격리 데이터: 1회차와 같음. 어두운 모드도 확인
- 검수자: 1회차와 다른 새 검수 에이전트. 1회차 결론과 지적 목록은 넘기지 않는다
- 확인할 기능: A5, A6, A7(상태 저장 변경 반영 후), A12, A13, A14
- 확인할 UX: 설계 3.6 전체, 쿠폰 예시를 처음 보는 사람이 알아채는지
- 기대 결과: 기능 항목 통과, 새 문제는 재현 절차와 함께 보고
- 대상 커밋: `d4bc088`

### 결과

A5, A6, A7, A12, A14는 통과했고 A13은 실패했다. 콘솔과 페이지 오류는 0건이었다. 차단 0건, 중요 5건, 개선 6건이 나왔고 모두 받아들여 고쳤다.

| 번호 | 심각도 | 지적 | 처리 |
|---|---|---|---|
| 1 | 중요 | 추가된 메서드의 안내 표시가 코드 첫 줄을 덮음 (A13 실패 원인) | 안내를 diff 위의 띠로 옮김. E2E에서 띠가 diff 영역 위에 있는지 확인 |
| 2 | 중요 | 900x600과 150%를 함께 쓰면 화면 읽기용 숨김 글자 때문에 문서가 24px 밀림 (A13 실패 원인) | 영역에 `position: relative`, 문서 스크롤 막음. E2E에서 휠을 굴려도 문서가 밀리지 않는지 확인 |
| 3 | 중요 | 매개변수가 바뀐 approve가 "본문"으로만 보이고, 새 테스트도 "바뀜" | 코어에 `signatureChanged`, 테스트의 변경 종류와 base 짝을 더함. "시그니처도 바뀜", 새 테스트는 "추가" |
| 4 | 중요 | 테스트 항목이 파일 전체를 보임 | 테스트도 메서드 범위만 잘라 비교 |
| 5 | 중요 | 테스트 표시와 위치가 저장소별로 기억되지 않음 | 상태를 저장소 경로별로 저장. 같은 비교면 위치까지, 다른 비교면 테스트 표시만 이어감 |
| 6 | 개선 | 메서드 밖 변경이 파일 전체를 칠해 구간 수와 맞지 않음 | 메서드 밖 구간만 강조하고 줄 번호를 안내 |
| 7 | 개선 | 호출 칩이 색으로만 구분되고, 이동한 호출의 base 줄이 강조되지 않음 | 칩에 ⚠, +, − 표시와 범례, 툴팁. 칩을 누르면 이전과 이후의 줄을 함께 강조 |
| 8 | 개선 | "본문" 라벨 대비 3.6~4.2:1 | 작은 라벨 글자 토큰(`--accent-ink`)으로 4.5:1 이상 |
| 9 | 개선 | 좁은 창에서 잘린 이름에 툴팁이 없고 호출 스택 이름이 말줄임 없이 잘림 | 목록 줄 버튼과 호출 스택에 툴팁, 말줄임 처리 |
| 10 | 개선 | 비교 표시가 "main 에 feature/coupon"으로 읽히고, 분석 뒤 초점이 body에 남음 | 접근성 이름을 "기준 main, 리뷰할 변경 feature/coupon"으로, 분석이 끝나면 선택된 줄로 초점, 오류와 빈 상태는 주 버튼으로 초점 |
| 11 | 개선 | 같은 비교나 목록에 없는 이름을 경고 없이 분석, 실패 문구에 이름이 없음, 고친 입력에 지난 오류가 남음 | 비교 선택에 경고, 실패 문구에 못 찾은 이름, 입력을 고치면 지난 오류 숨김 |

초점을 선택된 줄로 옮기면서 그 줄에서 누른 Enter가 다음 단계로 가지 않던 문제가 생겨 함께 고쳤다(이미 선택된 줄의 Enter는 다음 단계, 다른 줄의 Enter는 그 줄 선택).

## 3회차

### 계획 (시작 전)

- 대상: 2회차 지적을 고친 빌드(아래 커밋)
- 환경, 격리 데이터: 1, 2회차와 같음. 밝은 모드와 어두운 모드
- 검수자: 1, 2회차와 다른 새 검수 에이전트. 앞 회차 결론과 지적 목록은 넘기지 않는다
- 확인할 기능: A5, A6, A7, A12, A13, A14
- 확인할 UX: 설계 3.6 전체, 처음 보는 리뷰어가 쿠폰 예시를 알아채고 끝까지 읽는 흐름
- 기대 결과: 기능 항목 통과. 3회 뒤에도 해결되지 않은 문제가 남으면 문제, 추가 회차, 범위, 시간, 중단 영향을 정리해 승인받는다
- 대상 커밋: `8904d1a`

### 결과

A5, A6, A7, A12, A13, A14 모두 통과했다. A6은 통과지만 결함 1건이 함께 나왔다. 차단 0건, 중요 2건, 개선 7건이 나왔고 모두 받아들여 고쳤다.

| 번호 | 심각도 | 지적 | 처리 |
|---|---|---|---|
| 1 | 중요 | 진입점 바로 뒤 메서드가 바뀌지 않았으면 "이어지는 단계"가 비고 Enter가 멈춤 | 바뀌지 않은 경유 메서드를 건너뛰어 가장 가까운 다음 단계를 찾고 경유 이름을 함께 보임. 단위 테스트와 E2E 추가 |
| 2 | 중요 | 어두운 모드에서 강조된 줄의 글자 대비 약 2.5:1 | 강조 배경을 모드별 토큰으로 나누고 어두운 모드는 옅게 칠한 뒤 왼쪽 띠로 구분 |
| 3 | 개선 | 한 열 diff에서 줄바꿈된 삭제 줄이 들여쓰기 없이 이어짐 | 좁은 폭에서는 이전 쪽 줄바꿈을 끄고 가로로 스크롤 |
| 4 | 개선 | 끝에 닿으면 초점이 사라지고 안내가 없음 | 초점을 현재 목록 줄로 옮기고 첫 항목, 마지막 항목을 알림. E2E 추가 |
| 5 | 개선 | 900x600과 150%를 함께 쓰면 이름과 위치가 잘림 | 좁은 창에서 클래스 이름, "순서 변경" 글자, 전체 위치를 먼저 줄이고 테스트 이름은 한 줄 |
| 6 | 개선 | 브랜치 목록을 못 읽어도 "커밋이 없습니다" | 커밋 여부를 따로 확인해 "브랜치 목록을 읽지 못했습니다"와 git 오류 요약, SHA 직접 입력 안내 |
| 7 | 개선 | Kotlin 기타 테스트 파일에서 남은 구간이 강조되지 않고 안내가 틀림 | 남은 구간만 강조하고 기타 테스트용 안내. E2E 추가 |
| 8 | 개선 | 인자 안에서 새로 부른 호출 칩 대비 2.45:1 | 흐리게 하지 않고 회색 글자와 점선으로 구분 |
| 9 | 개선 | 삭제된 메서드의 안내가 맞지 않음, 기본 크기에서 현재 메서드 이름 잘림, 미확정 항목이 "1단계"로 읽힘 | 삭제된 메서드용 안내, 현재 이름 줄바꿈, 미확정은 "n번째"로 읽힘 |

## 마무리

- 3회 모두 기능 인수조건을 확인했다. A13은 2회차에 실패했고 3회차에 통과했다.
- 3회차 지적의 수정은 작성자 E2E(13개)와 단위 테스트, 직접 캡처로 확인했다. 정책상 4회차 독립 검수는 승인 없이 시작하지 않으므로, 3회차 수정 자체는 독립 검수를 거치지 않았다.
