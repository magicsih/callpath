# 3단계 새 화면 독립 검수 기록

테스트 계획의 "새 화면 독립 검수"에 따른 기록이다. 회차마다 시작 전에 계획을 적고, 끝난 뒤 결과와 처리를 덧붙인다. 스크린샷 원본은 NAS로 옮기고 여기에는 위치와 해시만 남긴다.

## 1회차

### 계획 (시작 전)

- 대상: `fe302df` 빌드(`apps/desktop/out`)
- 환경: macOS 26 (Darwin 25.6), Electron 44.7.1, Node 24, 화면 밝은 모드
- 격리 데이터: 쿠폰 표본(Java, Kotlin)으로 만든 임시 git 저장소, 실행마다 새 앱 데이터 폴더(`CALLPATH_USER_DATA`)
- 검수자: 구현자와 다른 검수 에이전트, 새 컨텍스트로 시작
- 확인할 기능: A5 테스트 토글, A6 단계 이동과 위치, A7 다시 열기 복원, A12 상태별 화면, A13 900x600과 150% 확대, A14 키보드만으로 처음부터 끝까지, 화면 읽기용 이름
- 확인할 UX: 설계 3.6 화면별 목적과 가장 강조하는 행동, 정보량, 상태 표현, 아이콘과 라벨, 쿠폰 예시의 "재고 차감이 결제 앞으로 이동"을 첫 흐름에서 알아챌 수 있는지
- 기대 결과: 기능 항목은 모두 재현되고, UX 문제는 화면, 재현 절차, 영향, 제안과 함께 보고된다
- 증거: 검수자가 직접 찍은 스크린샷과 실행 기록

### 결과

기능 A5, A6, A7, A12, A13, A14는 모두 통과했다. 차단 0건, 중요 2건, 개선 9건이 나왔고 모두 받아들여 고쳤다. 검수 중 구현자가 상태 저장과 워커 종료 처리를 고친 코드는 빌드에 반영되지 않은 상태였으므로 A7은 2회차에서 다시 본다.

| 번호 | 심각도 | 지적 | 처리 |
|---|---|---|---|
| 1 | 중요 | diff 줄 번호 옆이 네모 문자로 보임 | Monaco 아이콘 글꼴과 diff 기여 모듈을 번들에 넣음. E2E에서 글꼴 로드 확인 |
| 2 | 중요 | 어두운 모드 주 버튼 대비 3.16:1 | 주 버튼 배경 토큰(`--accent-strong`)을 따로 두어 4.5:1 이상 |
| 3 | 개선 | 브랜치를 못 찾은 실패인데 주 버튼이 다시 분석 | 오류 종류를 나눠 비교를 바꿔야 하는 실패는 비교 바꾸기가 주 버튼 |
| 4 | 개선 | 없는 경로와 파일 경로도 "Git 저장소가 아닙니다" | 경로 없음, 파일 경로, 저장소 아님을 나눠 안내 |
| 5 | 개선 | 커밋 없는 저장소에서 이유 없이 분석 버튼이 꺼짐 | "비교할 브랜치가 없습니다" 안내와 다시 읽기 |
| 6 | 개선 | 긴 이름이 잘리고 툴팁이 없음 | 목록, 호출 스택, 이어지는 단계에 전체 이름 툴팁. 테스트 이름은 두 줄까지 |
| 7 | 개선 | 바뀌지 않은 진입점에 빗금, 추가 메서드 왼쪽에 빈 빨간 줄 | 한쪽만 있는 코드는 diff 대신 한 칸 보기(추가는 초록, 삭제는 빨강) |
| 8 | 개선 | 900x600과 150% 동시 적용에서 diff가 4줄 | 좁은 창에서는 오른쪽 영역을 숨기고 가운데 위에 호출 경로 한 줄 |
| 9 | 개선 | 다음 단계 버튼이 다른 버튼과 같은 모양 | 다음 버튼을 주 버튼으로 |
| 10 | 개선 | 체크박스 초점에서 t 무시, 이동 중 "no diff result available" 오류 | 체크박스에서도 t 동작. diff 모델을 한 쌍만 두고 내용만 바꿔 오류 제거. E2E에서 페이지 오류 0건 확인 |
| 11 | 개선 | "main와 main", 헤더 "진입점 2", 생성자가 "OrderService OrderService" | 조사 없는 문구로 바꿈, 헤더는 흐름 수와 바뀐 메서드 수, 생성자는 "생성자"로 표시 |

검수자 제안 중 흐름 제목에 순서 변경 수를 붙이는 것과 줄 강조를 진하게 하는 것도 반영했다.

## 2회차

### 계획 (시작 전)

- 대상: 1회차 지적을 고친 빌드(아래 커밋)
- 환경, 격리 데이터: 1회차와 같음. 어두운 모드도 확인
- 검수자: 1회차와 다른 새 검수 에이전트. 1회차 결론과 지적 목록은 넘기지 않는다
- 확인할 기능: A5, A6, A7(상태 저장 변경 반영 후), A12, A13, A14
- 확인할 UX: 설계 3.6 전체, 쿠폰 예시를 처음 보는 사람이 알아채는지
- 기대 결과: 기능 항목 통과, 새 문제는 재현 절차와 함께 보고
