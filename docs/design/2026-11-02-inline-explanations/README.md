# 코드 가상 주석과 지도 흐름 설명 v1

상태: v1 승인. 2026-11-02 사용자가 화면 시안과 자동 전송 범위, 테스트 계획을 승인했다. 구현 진행 중.

[화면 시안](prototype.html), [테스트 계획](test-plan.json)

## 목표와 범위

코드 편집기를 열면 클래스의 역할과 본문 실행 순서를 코드 사이의 가상 주석으로 읽는다. 지도에서는 진입점부터 어떤 클래스를 거쳐 무엇을 하는지 따라 읽는다. 비교 리뷰의 이전 코드와 이후 코드, 둘러보기의 클래스 코드와 투어에 적용한다. 기존 오른쪽 설명은 추가 요약을 받는 보조 기능으로 유지한다.

요청의 “LLM 설정이 되어 있으면 바로 설명 작성”에 따라, LLM이 켜져 있고 주소와 모델이 저장되어 있으면 코드가 준비되는 즉시 설명을 자동 요청한다. 키 없는 로컬 모델도 지원한다. 꺼져 있으면 보내지 않는다. 기존 “전송마다 미리보기 후 보내기” 규칙 D15는 이 자동 설명에 한해 대체한다. 보조 설명 버튼은 기존 미리보기를 유지한다.

## 화면과 동작

### 코드

- 클래스 선언과 애노테이션 위: 이 클래스의 책임, 입력과 결과, 관련 클래스와의 관계를 2~3문장으로 설명한다. 한 파일에 클래스가 여럿이면 해당 선언마다 붙인다. 메서드 일부만 보이는 리뷰에서는 클래스 요약을 편집기 상단에 두고 현재 보이는 메서드와 연결한다.
- 본문: 의미 있는 각 코드 줄 앞에 1~2줄 설명을 넣는다. 필드 묶음, 메서드 시작, 값 계산, 조건과 반복, 다른 메서드 호출, 외부 작업, 상태 변경, 반환을 설명한다. import, 빈 줄과 닫는 괄호마다 같은 말을 반복하지 않는다.
- 설명은 문법을 한국어로 바꾸는 데 그치지 않고 값의 의미, 왜 다음 메서드를 부르는지, 어떤 상태가 바뀌는지 적는다. 코드에서 확인할 수 없는 의도는 단정하지 않는다.
- 위에서 아래로 읽으며 호출 순서를 이해할 수 있게 짧게 쓴다. 설명이 길면 그 자리에서 펼치며, 설명이 도착할 때마다 읽던 줄이 이동하지 않게 스크롤을 보존한다.
- 상단에 `가상 주석` 표시 토글, 생성 상태, `다시 작성`, 요청 중 `멈추기`를 둔다. 숨기기는 네트워크 중단이나 LLM 설정 끄기와 구분한다. 다시 작성만 캐시를 무시한다.
- 가상 설명을 복사해 읽을 수 있게 하되 코드 선택과 복사에는 원래 코드만 들어간다. 검색, 줄 번호, diff, 줄 메모와 호출 단계 이동은 원본 위치를 사용한다. 파일과 Git 작업 트리는 수정하지 않는다.
- diff에서는 양쪽 코드를 구별해 각각 그 시점의 설명을 단다. 삭제된 코드에 이후 설명을 붙이지 않는다. 한 열 비교에서도 출처와 줄 번호가 바뀌지 않는다.

### 지도

- 지도에 `흐름 읽기`를 두고 실제 분석 결과의 진입점을 고른다. 첫 진입점을 기본으로 선택하되 전체 저장소를 무차별 요청하지 않는다. 진입점이 없으면 기존 공개 API 투어를 같은 방식으로 사용한다.
- 선택한 진입점의 정적 투어를 이용해 단계 번호와 진행 방향을 지도에 표시한다. LLM은 각 단계가 하는 일과 앞뒤 관계를 설명한다. 기존의 패키지와 역할 배치는 유지한다.
- 단계 설명을 누르면 해당 클래스와 선을 강조하고 해당 메서드 코드를 열 수 있다. 코드가 열리면 가상 주석을 자동 작성한다. `다음`으로 코드와 지도 단계를 함께 이동할 수 있다.
- 조건과 반복, 다시 부르는 단계, 인터페이스 구현 후보, 확인되지 않은 연결은 분석 결과의 구분을 유지한다. LLM이 만든 연결이나 실행되지 않은 경로를 확정된 호출로 그리지 않는다.
- 코드에 대한 가상 주석과 지도의 흐름 설명은 구분해 저장한다. 같은 파일을 다른 진입점에서 읽어도 기존 코드 설명을 재사용한다.

### 상태와 자동 전송

| 상태 | 표시와 다음 행동 |
| --- | --- |
| LLM 꺼짐 또는 주소와 모델 없음 | 코드를 바로 표시한다. 짧은 설정 진입만 제공하고 요청하지 않는다 |
| 캐시 적중 | 설명을 즉시 표시한다. 추가 요청하지 않는다 |
| 작성 중 | 코드를 계속 읽을 수 있다. `설명 작성 중`, `멈추기`와 전송 범위를 표시한다 |
| 일부 완료 | 검증이 끝난 구간부터 표시한다. 나머지는 작성 중임을 구별한다 |
| 실패 또는 응답 형식 오류 | 코드는 유지한다. 실패 원인, `다시 작성`, `LLM 설정`을 제공한다. 자동 반복 요청하지 않는다 |
| 사용자 중단 또는 다른 파일로 이동 | 요청을 취소한다. 완성된 캐시는 유지하고 불완전한 답을 완료로 저장하지 않는다 |
| 큰 파일 | 현재 클래스와 메서드 중심으로 24,000자 이내 구간을 요청한다. `이 구간 설명` 범위를 표시하고 나머지는 읽을 때 순서대로 요청한다 |

설정 화면의 기존 전송 안내를 자동 설명 동작에 맞춘다. 코드 화면 상단에는 실제 대상 호스트와 모델, 보내는 파일과 범위, 기록 보기를 표시한다. 지도는 선택한 흐름의 메서드와 호출 구조만 보낸다. 저장소 전체 파일, 미커밋 변경, 키 파일은 전송 대상에 넣지 않는다. 기존 전송 기록에는 실제 요청과 답을 남기며 키와 헤더 값을 기록하지 않는다.

## 구현 구조

| 부분 | 책임 |
| --- | --- |
| `packages/llm` | 코드 설명과 흐름 설명 요청 생성, 줄이 표시된 입력, 응답 형식과 범위 검증. 기존 OpenAI 호환 클라이언트와 24,000자 코드 상한을 재사용한다 |
| 데스크톱 main | 지정 커밋에서 코드 읽기, 설정 확인, 요청 중복 방지, 대기열과 취소, 로컬 캐시, 실제 전송 기록 |
| shared API와 preload | 요청 번호, 소스 식별자, 검증된 설명, 진행과 취소 전달. 렌더러에는 키를 내보내지 않는다 |
| `CodeView`, `DiffView` | 원본 모델을 그대로 두고 줄 사이의 설명 공간을 추가한다. 설명 토글과 줄 위치, diff와 메모 동작을 지킨다 |
| 지도와 투어 | 정적으로 확인한 단계와 연결을 표시하고, LLM의 설명 문구만 결합한다 |

[Monaco의 `changeViewZones`](https://microsoft.github.io/monaco-editor/typedoc/interfaces/editor_editor_api.editor.ICodeEditor.html#changeviewzones)로 코드 줄 사이에 별도 DOM을 놓는다. 줄 끝에만 한 줄을 넣을 수 있는 injected text보다 긴 한국어 설명과 줄바꿈에 적합하다. DOM에는 모델 답을 텍스트로 넣고 HTML을 실행하지 않는다. 화면 크기, 확대와 글자 크기가 바뀌면 설명 높이를 다시 계산한다.

응답은 클래스 요약과 `소스 식별자, 파일 줄, 설명 종류, 설명` 목록으로 받는다. 지도 설명은 분석 결과가 부여한 단계 번호를 참조한다. 요청에 없는 파일, 시점, 줄, 단계는 표시하지 않는다. 줄 번호나 단계가 모호하면 요청 실패로 처리하며 임의 위치에 붙이지 않는다. 부분 완료는 구간 단위로 유효한 결과를 받은 경우만 표시한다.

캐시 키는 저장소 식별자, 커밋 SHA, 경로, 코드 구간, 모델과 끝점, 프롬프트 버전으로 구성한다. 지도는 진입점도 포함한다. 키와 헤더 값은 캐시 키와 캐시 본문에 넣지 않는다. 화면이 바뀌면 이전 요청 번호로 온 답은 현재 코드에 반영하지 않는다. 빠른 탐색은 400ms 동안 합쳐 한 번만 요청하고, 동시 요청은 1개로 제한한다. 상한이나 오류에서 자동 재시도하지 않는다.

## 검증과 적용

`test-plan.json`의 L3 개발 환경 전체 회귀와 독립 실행 검수 3회를 사용한다. 네이티브 SDK와 기기 기능은 바꾸지 않으므로 macOS Electron 개발 환경과 Linux CI로 확인한다. LLM은 로컬 모의 서버를 사용하며 실제 회사 코드를 외부에 보내 검수하지 않는다.

가상 설명 표시, 자동 요청 조건, 취소, 소스 위치 일치, 코드 복사와 파일 불변, 캐시 재사용, diff 양쪽과 지도 이동을 실패 테스트부터 구현한다. 새 자동 경로와 수동 보조 설명 경로를 각각 확인하고, 기존의 전송 0건 검증은 새 정책에 맞춰 `LLM 꺼짐`과 `캐시 적중`에 남긴다. 기존 메모, 게시, 키 파일과 비밀값 보호도 회귀 실행한다.

구현은 별도 브랜치와 한국어 Ready PR로 제공한다. 마켓 배포나 새 자격증명은 없다. 동작을 되돌릴 때는 해당 PR을 되돌리고 새 설명 캐시만 사용하지 않도록 한다. 사용자 설정과 기존 기록은 삭제하지 않는다.

검토할 범위: 위 화면 구성, 자동 전송 조건과 범위, L3 개발 환경 검수. 독립 검수는 구현자와 다른 에이전트가 실행하며 3회 뒤 문제가 남으면 추가 실행 전에 확인받는다.
