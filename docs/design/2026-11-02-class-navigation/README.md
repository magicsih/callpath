# 클래스 검색과 코드 이동

설계 v1. 상태: 구현 전 검토. 기준은 `main`의 `349edaf9130b4bbb0e482cfe9e522ea84cc1e157`, 공개 버전 0.1.1이다. 사용자가 요청한 클래스 검색, 선언과 구현체 이동을 추가한다. [조작 가능한 화면 시안](prototype.html), [테스트 계획](test-plan.json).

## 찾고 따라 읽기

저장소를 둘러보거나 비교 코드를 읽는 중에 클래스 이름으로 파일을 열고, 코드에서 참조한 클래스와 인터페이스를 따라 읽는다. 돌아올 때는 원래 커밋과 코드 위치를 복원한다. 기존 코드 왼쪽, 구간별 설명 오른쪽의 분할 화면을 그대로 사용한다.

| 동작 | 화면과 결과 |
| --- | --- |
| 클래스 검색 | 상단의 `클래스 검색` 또는 Cmd+O, Windows와 Linux는 Ctrl+O. 이름, 전체 패키지 이름, 경로로 찾는다. 화살표와 Enter로 선택한다 |
| 검색 결과 선택 | 클래스 종류, 패키지와 파일 경로를 함께 보이고 선택한 선언의 실제 파일 줄에서 코드를 연다. 테스트와 중첩 클래스도 검색 대상이다 |
| 선언 따라가기 | 코드의 클래스명에서 Cmd 클릭, Windows와 Linux는 Ctrl 클릭, 또는 F12와 우클릭의 `정의로 이동`. 클래스와 인터페이스의 선언으로 간다 |
| 구현체 따라가기 | 인터페이스나 상위 클래스의 코드 도구막대와 우클릭의 `구현체로 이동`, Cmd+Alt+B 또는 Ctrl+Alt+B. 하나면 바로 열고 여럿이면 종류와 경로가 있는 목록에서 고른다 |
| 상위 타입으로 이동 | 클래스 맥락의 상위 타입을 누르면 해당 선언의 코드가 열린다. 지도에서의 기존 클래스 선택과 투어 시작도 유지한다 |
| 돌아오기 | 코드 위의 이전과 다음 버튼, Alt+Left와 Alt+Right. 파일, 커서와 스크롤, 지도나 투어의 원래 위치, 비교 시점을 복원한다 |

둘러보기는 현재 커밋을 검색한다. 비교와 PR 리뷰에서는 이전 코드와 이후 코드를 구별하고, 검색 창에도 현재 시점과 커밋을 표시한다. 바뀌지 않은 클래스도 찾는다. 디렉터리로 분석 범위를 좁혔다면 그 범위를 검색 창에 표시하고 같은 범위에서 찾는다. 검색과 이동은 LLM 설정 없이 동작한다. 코드를 연 뒤의 자동 설명은 기존 설정을 따른다.

검색은 정확한 이름, 앞부분 일치, 부분 일치 순으로 정렬하고 패키지와 경로로 동명이인을 구별한다. 클래스, 인터페이스, enum, record, Kotlin data class와 object, 중첩 클래스를 포함한다. 처음에는 이름 순 목록을 보여 주고 입력하면 좁힌다. 많은 결과는 개수와 목록 스크롤로 처리하고 잘린 결과를 전체처럼 표시하지 않는다.

이번 범위의 코드 내 이동은 클래스와 인터페이스 등 타입 선언을 대상으로 한다. 임의의 메서드 호출과 오버로드를 IDE처럼 모두 해석하는 기능은 포함하지 않는다. 구현 목록은 소스에 선언된 관계를 보여 주며 의존성 주입 설정이나 실행 시 실제 선택까지 확정하지 않는다.

## 상태와 잘못된 연결 방지

- 분석 중에는 검색 창에서 진행 상태를 보이고 완료 후 입력한 질의를 적용한다. Esc나 닫기는 원래 초점과 읽던 자리를 복원한다.
- 빈 결과에는 `일치하는 클래스가 없습니다`를 보이고 질의를 유지한다. 구현체가 없거나 외부 라이브러리처럼 저장소에 소스가 없으면 이유를 짧게 보이고 원래 코드를 유지한다.
- 같은 이름의 클래스가 여럿이면 패키지, 명시 import, Kotlin import 별칭과 중첩 범위를 적용한다. 선언을 하나로 결정할 수 없으면 후보를 고르게 하며 임의의 첫 결과로 이동하지 않는다. 문자열과 주석의 같은 단어는 코드 참조로 취급하지 않는다.
- 직접 구현뿐 아니라 중간 인터페이스와 추상 클래스를 거친 구현도 찾는다. 후보마다 추상 여부와 파일을 표시하고 중복과 순환 관계를 막는다. 해석할 수 없는 관계는 확인된 관계와 구분한다.
- 검색 결과를 받기 전에 파일이나 커밋을 바꾸면 지난 답이 새 화면을 이동시키지 않는다. 숨겨진 화면의 단축키와 닫힌 검색 창의 이벤트를 해제한다.
- 탐색 기록은 현재 실행의 저장소와 커밋별로 최대 50개를 유지한다. 사용자 파일, Git 작업 트리, 메모와 기존 설정은 변경하지 않는다.

## 구현 경계

기존 분석기는 `FileIndex`에 클래스의 이름, 종류와 선언 범위를 갖고 있지만, 지도는 테스트와 중첩 클래스를 합치거나 제외한다. 따라서 지도 칩 목록을 전체 클래스 색인으로 쓰지 않는다. 코어에 기존 파서의 클래스 색인과 import 정보를 사용하는 탐색 모듈을 두고, 같은 커밋의 이름 검색과 선언, 상속 관계를 함께 해석한다. 현재 지도 관계의 단순 이름 추정 결과만으로 코드 이동을 확정하지 않는다.

파일을 읽고 색인을 만드는 일은 기존 분석 워커에서 실행한다. main과 preload는 저장소, SHA, 상대 경로와 위치를 검증한 요청과 결과만 전달한다. 검색 창과 코드 이동, 이력은 공통 탐색 구성요소를 쓰고 둘러보기와 비교 화면의 기존 코드 보기에 연결한다. 원본 줄 번호와 투어 조각의 첫 파일 줄, diff의 이전과 이후를 변환하는 경계를 명시한다. 탐색 색인 캐시는 커밋, 디렉터리와 분석기 버전으로 구별하고 기존 캐시 파일을 삭제하지 않는다.

Monaco의 [DefinitionProvider](https://microsoft.github.io/monaco-editor/typedoc/interfaces/editor_editor_api.languages.DefinitionProvider.html)와 [ImplementationProvider](https://microsoft.github.io/monaco-editor/typedoc/interfaces/editor_editor_api.languages.ImplementationProvider.html)를 사용한다. 설치된 0.57.0의 `monaco.d.ts`에서도 두 등록 API를 확인했다. 모델은 저장소, 커밋과 경로가 다른 URI를 사용하며 등록과 모델, 이벤트를 보기 종료 시 해제한다. 새 언어 서버나 의존성을 추가하지 않고 Java와 Kotlin의 타입 탐색을 같은 기능 범위로 제공한다.

대안은 지도 목록에 검색칸만 추가하는 방법과 언어 서버만 사용하는 방법이다. 전자는 중첩 클래스, 테스트와 코드 내 이동을 해결하지 못한다. 후자는 Java 실행 환경과 별도 Kotlin 서버가 없는 사용자에게 동작하지 않아 이번 기본 기능에 사용하지 않는다. 기존 LSP 정밀 호출 분석은 유지한다.

## 검증과 배포

L3 개발 환경 전체 회귀, 실제 앱 실행과 독립 화면 검수 3회로 계획한다. 핵심 경로는 `OrderService` 검색, 코드의 `PaymentClient` 선언 이동, 구현체 두 개 중 `CardPaymentClient` 선택, 이전 코드 위치 복원이다. Java와 Kotlin, 같은 이름의 다른 패키지, import 별칭, 중첩과 테스트 클래스, 간접 구현, 외부 타입, 빈 결과, 비교 시점과 투어 원본 줄, 취소와 오래된 답도 검증한다. 작은 창 900×600, 150% 확대, 밝은 테마와 어두운 테마, 키보드만 사용한 흐름을 확인한다.

승인 후 실패하는 코어 테스트와 E2E부터 작성하고 구현한다. 전체 단위, 타입 검사와 빌드, Ubuntu와 두 macOS 환경의 전체 E2E 및 설치 패키지 검사를 확인한 뒤 Ready PR로 반영한다. 새 검색 창과 코드 이동 UI의 독립 검수는 같은 후보에서 3회 실시한다. LLM은 모의 끝점을 사용하고 사용자 키체인, OS 클립보드와 모바일 기기는 사용하지 않는다.

배포 계획은 기존 Homebrew 채널의 정식 0.1.2 공개까지다. 서명과 Apple 공증, 공개 다운로드 파일과 실제 cask 설치본의 탐색 흐름까지 확인한다. 실패하면 해당 단계에서 중단하고 기존 0.1.1을 임의로 덮어쓰지 않는다. 수정이 필요한 경우 새 후보를 검증한다. 원시 화면과 로그, 배포 원본은 NAS에서 크기와 해시를 검증한 후 로컬 사본을 정리하고 텍스트 기록과 위치를 남긴다.

구현 착수는 이 설계와 테스트 계획을 함께 승인받은 뒤 진행한다. 승인 시 위 Homebrew 공개 범위도 포함한다.
